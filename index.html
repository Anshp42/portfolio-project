Project 01 — Interactive Desktop Application

Deadly Desert Lab

Stack: Java · Object-Oriented Programming · Version Control

Problem Statement

Developing engaging, logic-driven simulation loops requires efficient collision detection, state management, and real-time asset rendering without introducing CPU processing bottlenecks.

Process & Reflection

I designed this system by separating rendering surfaces from the core simulation logic loops. A significant challenge was optimizing the asset calculation updates to prevent frame drops during complex interactions. By refactoring the update cycle to utilize delta-time rendering and tracking coordinates via structural vectors, I achieved stable, cross-platform performance execution.

Project 02 — Command Line Interface (CLI) Application

Tic-Tac-Toe

Stack: Java · 2D Arrays · Scanner (Console I/O)

Problem Statement

A two-player Tic-Tac-Toe game that runs entirely in the terminal. The goal was to let two people play on the same computer with clear turn prompts, a board that redraws after every move, and rules that block invalid plays.

Process & Reflection

I represented the board as a 3×3 grid of characters and built a turn loop that alternates between Player 1 (X) and Player 2 (O). The trickiest part was handling bad input, so I added a validation loop that rejects moves landing off the board or on a square that is already taken, and only accepts a move once it is valid. To decide the outcome, a separate method checks all three rows, all three columns, and both diagonals after each move, and the game declares a draw if all nine squares fill without a winner.

Project 03 — Engineering Utility Application

Engineering Calculator

Stack: Java · Object-Oriented Programming

Problem Statement

Engineers frequently reach for the same formulas and recompute them by hand, which is slow and easy to get wrong. This Java application lets a user enter their values and instantly returns the calculated result, so common engineering calculations can be run quickly and consistently.

Process & Reflection

I built the calculator in Java, organizing each formula so the user can choose a calculation, enter the required inputs, and get an answer right away. The main challenge was validating the numbers a user types so that invalid or out-of-range input does not crash the program. Splitting the work into a separate method for each formula kept the code readable and made it easy to add new calculations later.

Project 04 — Web Application · Team Project (Congressional App Challenge)

School Bus Dismissal App

Stack: Next.js · React · TypeScript · Tailwind CSS · Supabase (Postgres)

Problem Statement

At dismissal, students often struggle to find which bus they are assigned to, which creates confusion and slows everyone down. Our team set out to make dismissal easier by building a web app where a student can instantly look up their assigned bus, with an admin side that lets staff manage and update assignments.

Process & Reflection

I built this as part of a four-person team for the Congressional App Challenge. We developed it as a Next.js and React application backed by a Supabase database, with a student-facing lookup page, a separate admin panel, secure staff logins using hashed passwords, and API routes to look up and assign buses. The biggest lesson for me was working in a shared codebase: we used Git and GitHub to split the work, review one another's changes, and keep our features from conflicting. Connecting the front-end pages to the database and API routes pushed me well beyond a solo project.
